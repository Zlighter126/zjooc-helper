# ZJOOC 批量看课助手（Chrome / Edge 扩展）

在「浙江省高等学校在线开放课程共享平台」(zjooc.cn) 上，把课程章节里的所有视频同时打开、
多标签页并行播放，并按平台自身的进度接口记录学习进度。

---

## 一、安装（一次性，约 1 分钟）

1. 下载/保留本文件夹：`zjooc-helper`（含 `manifest.json`）。
2. 打开 Chrome，地址栏输入 `chrome://extensions/`（Edge 为 `edge://extensions/`）。
3. 右上角打开 **开发者模式**。
4. 点 **加载已解压的扩展程序**，选择 `zjooc-helper` 文件夹。
5. 扩展列表中出现「ZJOOC 批量看课助手」即安装成功；可点拼图图标把它固定到工具栏。

> 需要 Chrome 111 及以上（`world: "MAIN"` 内容脚本）。

## 二、必做的一次性设置：允许本站播放声音

浏览器的自动播放策略会拦截多个后台标签页的**有声**播放；而 Chrome 又会暂停后台的**静音**视频。
所以必须先让浏览器允许 zjooc.cn 自动出声：

1. 地址栏输入 `chrome://settings/content/sound`
2. 在「允许播放声音」里 **添加** `https://www.zjooc.cn`

（不设置也能跑，但会自动退回静音，后台标签页可能被 Chrome 暂停，进度会停。）

## 三、运行

1. 先在浏览器里正常登录并进入该课程页面（地址形如
   `https://www.zjooc.cn/ucenter/student/course/study/<课程ID>/notice`）。
2. 点工具栏上的扩展图标，弹窗会自动填好 **课程 ID**。
3. 设置：
   - **同时播放数**：默认 6；想"全部同时打开"就填 76（很占带宽/内存，不建议超过 8~10）
   - **倍速**：默认 2；实测 8 倍也能正常记录（平台不校验真实耗时），建议 2~4 更稳
4. 点 **开始**。扩展会自己开标签页、进课程、打开视频、播放、上报进度，
   每个视频到 100% 自动关掉该标签页并补开下一个。
5. 进度看弹窗：`运行中 12/60`；想停就点 **停止**（会关闭它开的标签页）。

## 四、它做了什么（原理）

- 平台进度的唯一来源是前端每 20 秒调用
  `/learningmonitor/api/learning/monitor/videoPlaying`
  上报 `{chapterId, courseId, playTime, percent}`，其中百分比 ≥95% 时计为 100%。
- 每个标签页打开一个视频，脚本读取 `<video>` 的**真实播放位置**，用站点自带的
  `Service.get(...)` 按同样规则上报，因此进度与真实观看一致（只是加速、并行）。
- 深度链接直接打开会被路由守卫弹回课程列表，所以脚本走应用内路由：
  `/build/list` → `/plan` → `/plan/detail/<章节ID>`。
- 把 `document.hidden/visibilityState` 伪装为可见，避免站点/浏览器以为页面在后台。

## 五、注意事项

- 视频数据走线上带宽：并发 6 路 720P 约 20~30 Mbps，注意流量。
- 平台若日后加入服务端校验（例如比对真实耗时），加速/并行可能被判定无效，请自行评估风险。
- 弹窗里的「课程 ID」必须与当前登录账号已选课程一致。
- 失效时可在任意 zjooc 页面按 F12 看控制台报错，或在弹窗里查看最近日志。

## 六、常见问题

**1. 弹窗一直显示「正在扫描章节…」不动**
按顺序排查：
- 课程 ID 是否正确（必须是你已选的课程，形如 `8a2212f3a079851507...`）；
- 是否在同一个 Chrome 里登录了 zjooc；
- 是否允许了本站声音（见第二节）；
- 扩展是否被更新过：改过代码后要去 `chrome://extensions/` 点该扩展的 **刷新** 按钮，
  然后 **停止 → 开始**。
- 若仍不动：打开 `chrome://extensions/` → 该扩展的「Service Worker」→ 查看控制台报错，
  或在课程标签页按 F12 看 Console 是否有 `page.js` 的报错。

**2. 进度不涨 / 视频暂停**
多半是浏览器把后台标签页的静音视频挂起了。确认 `chrome://settings/content/sound`
里已把 `https://www.zjooc.cn` 加到「允许播放声音」。

**3. 页面自动刷新后任务就停了**
- 若是**整页刷新**（标签页重新加载）：新版会自动恢复——后台记录着该页签正在看的章节，
  刷新后重新下发同一章节继续播，不会丢任务。同一页签反复刷新超过 6 次才会放弃并补新页签。
- 若刷新后跳到**登录页 / 首页并显示「请登录」**：说明**登录态被站点踢了**（平台对同一账号
  多端登录会互踢，或长时间后 token 过期）。这时扩展会打印「任务停止：登录已失效…」并关掉
  它开的页签。处理：重新登录，关掉手机/另一台电脑上的同账号登录，再点开始。
- 另外并发开太多页签容易触发内存回收，Chrome 会把后台页签“丢弃”并重新加载。
  这也是刷新频发的常见原因，把「同时播放数」降到 4~6 更稳。

**4. 想中途停止**
点弹窗里的「停止」，扩展会关掉它开的所有标签页。

## 七、文件说明

| 文件 | 作用 |
| --- | --- |
| `manifest.json` | 扩展清单（MV3） |
| `page.js` | 页面内脚本（MAIN world）：路由跳转、播放、上报、完成检测 |
| `bridge.js` | 隔离世界桥接：页面 ↔ 后台消息转发（含旧版 Chrome 的注入兜底） |
| `background.js` | 任务队列：扫描章节、按并发开标签页、完成/失败回收、补开下一个、看门狗 |
| `popup.html` / `popup.js` | 控制面板 |
